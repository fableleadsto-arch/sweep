# TradeOps market validation

2026-10-28. Status: **Planned**. Customer interviews, commitments, willingness to
pay, time savings and retention have **not** been measured. This document records
testable hypotheses, not market findings.

Initial segment hypothesis: small exporters/importers, customs-service providers
and freight brokers manually comparing invoices and packing lists. Proposed value:
reduce time spent finding/rechecking mismatched quantities and missing references
while preserving a human decision and source evidence. Validate whether this is
frequent and costly enough before broadening the document types or adding prices.

## Interview and pilot protocol

When the user provides suitable participants, obtain explicit permission before
contacting them. Ask for a walkthrough of a recent reconciliation, the source
formats/languages, volume, review time, costly errors, current software and actual
approval responsibilities. Ask which information must stay on-device, who buys,
how they evaluate replacements and what would stop adoption. Do not solicit raw
customer documents without a separate authorized handling/retention agreement.

Record date, consent, role, company-size band, anonymized workflow facts and exact
evidence for each hypothesis. Separate observations from inferred needs. Use an
approved redacted or synthetic example before any live pilot. Do not send email,
create external accounts, charge customers or publish claims as part of this plan.

## Experiments and decisions

| Hypothesis | Measurement | Current evidence |
| --- | --- | --- |
| Quantity/reference review is a recurring pain | Frequency, baseline time, examples of actual errors | None |
| Source-linked review is trusted | Time to verify findings, corrections, false-positive burden | None |
| Local standalone processing matters | Policy restrictions and hardware profile | User's product requirement; no broader market conclusion |
| MVP produces value | Time to first completed review and repeated use over agreed pilot | None |
| A paid plan is viable | Explicit buying process, pricing experiments and measured cost | None |

Pilot reporting should include activation, completed workflows, correction/review
time, abandoned workflows and support effort, using explicit opt-in collection or
local exports. No hidden telemetry. Compare to the same user's existing process
with similar document difficulty; do not attribute improvements solely to AI
without a comparable baseline. Billing remains deferred until costs and demand
support a concrete experiment. No hardcoded price or revenue projection exists.
